# Healthcare Data Preprocessing Pipeline (VitalDB)

A reusable, `scikit-learn`-compatible preprocessing pipeline for real surgical
patient data from [VitalDB](https://vitaldb.net/dataset/), built for
downstream machine learning applications (e.g. mortality / ICU-admission
prediction). Built as a data science portfolio project — every design
decision below is deliberate and documented, not a default left in place.

deployed link:https://vitaldb-healthcare-preprocessing-yxa79wkc5csfhru4pugbyq.streamlit.app/

## Why this dataset

VitalDB is high-fidelity, real hospital data — 6,388 surgical cases from
Seoul National University Hospital, published in a peer-reviewed *Scientific
Data* paper, covering 196 intraoperative monitoring parameters, 73
perioperative clinical parameters, and 34 lab parameters. Unlike a
pre-cleaned Kaggle CSV, this data has genuine, clinically-explainable
messiness: MNAR missingness (labs are only drawn when clinically indicated),
device/entry-error outliers, and mixed ordinal/nominal categoricals — exactly
the problems this pipeline is built to handle.

**Access method:** the pipeline pulls directly from VitalDB's public API
(`api.vitaldb.net`) — no bulk download of the ~30–90GB waveform archive is
needed for the tabular clinical/lab data this project uses.

## Pipeline stages and why each technique was chosen

| Stage | Technique | Reasoning |
|---|---|---|
| **Duplicates** | Dedupe on `caseid`, not full-row hash | A patient with two separate surgeries isn't a duplicate — naive row-hashing would risk deleting real clinical events |
| **Outliers** | Clinical plausibility bounds (literature-based reference ranges) | A generic z-score/IQR rule would flag a genuinely critical (but real) patient value as noise and discard it. Bounds distinguish *impossible* values (sensor/entry error) from *extreme-but-real* ones (a genuinely sick patient), which are clinically important and must be kept |
| **Missing values** | **MICE** (`IterativeImputer`), with KNN kept as a comparison baseline via `compare_imputers()` | MICE models each missing column as a function of *all* other columns via chained regression — standard practice in clinical/epidemiological statistics for correlated, mixed-missingness lab data, more principled than a single deterministic KNN pass. A `<col>_was_missing` indicator is added per column, since missingness itself is informative in EHR data (a lab often wasn't ordered because it wasn't clinically indicated, not because it was lost) |
| **Imputation safety** | `ImputationBoundsClipper` | MICE is regression-based and can extrapolate an estimate outside a physiologically valid range, unlike KNN. Any such value is clipped back into the clinically plausible bound right after imputation |
| **Normalization** | **RobustScaler** (median/IQR) | Preop labs are right-skewed with genuine extreme values from critically ill patients. StandardScaler's mean/std would be distorted by exactly those values; RobustScaler is far less sensitive to that skew |
| **Categorical encoding** | Ordinal (ASA class) + **frequency encoding** (nominal fields) — deliberately not one-hot | ASA has real clinical ordering that one-hot would discard. For nominal fields like `optype`/`department`, one-hot risks exploding dimensionality on moderate-cardinality columns; frequency encoding compresses each category into one informative numeric column without needing an outcome label (so, unlike target encoding, it can't leak information) |
| **Feature engineering** | BMI, surgery/anesthesia duration, induction-to-incision time, abnormal-preop-lab-count | All derived from known predictors in the anesthesiology literature, not arbitrary column math |
| **Output scope** | `FeatureSelector` | Keeps only the pipeline's intentional feature set (ID, configured numeric/categorical columns, and everything derived from them), dropping raw VitalDB columns (`cormack`, `tubesize`, `intraop_ebl`, etc.) the pipeline was never designed to clean |
| **Reusability** | Every step is an `sklearn.base.TransformerMixin`, assembled into a single `Pipeline` | `pipeline.fit_transform()` on training data, `pipeline.transform()` alone on new data — this is what makes it a genuine pipeline rather than a one-off script |
| **Validation** | Schema checks, completeness checks, imputation-plausibility checks, scaling sanity checks, before/after distribution comparison | Produces a pass/fail report plus a Markdown quality report — a real data-quality gate, not just a row-count comparison |

## Installation & usage

```bash
pip install -r requirements.txt

# 1. Pull raw data from the VitalDB API (no bulk download needed)
python vitaldb_api_access.py --out data/raw/vitaldb_raw.csv

# 2. Run the preprocessing pipeline
python preprocessing_pipeline.py --input data/raw/vitaldb_raw.csv \
                                  --output data/processed/vitaldb_processed.csv

# Optional: compare MICE vs KNN imputation accuracy on this data
python preprocessing_pipeline.py --input data/raw/vitaldb_raw.csv \
                                  --output data/processed/vitaldb_processed.csv \
                                  --compare-imputers

# 3. Validate the processed output's quality
python validate_pipeline_output.py --input data/raw/vitaldb_raw.csv \
                                    --report-out reports/quality_report.md

# 4. Run the test suite
pytest test_pipeline.py -v
```

### Reusing the fitted pipeline on new data

```python
from preprocessing_pipeline import build_pipeline
import joblib

pipeline = build_pipeline(imputation_strategy="mice")
pipeline.fit(training_df)
joblib.dump(pipeline, "fitted_pipeline.joblib")

# later, on new incoming data:
pipeline = joblib.load("fitted_pipeline.joblib")
processed_new = pipeline.transform(new_raw_df)
```

Only `NUMERIC_COLS`, `CATEGORICAL_*_COLS`, and `CLINICAL_BOUNDS` at the top of
`preprocessing_pipeline.py` are VitalDB-specific — swap those for another
dataset's schema and the pipeline works unchanged.

## Results from a real run

Full run against the live VitalDB API (6,388 cases, 74 raw clinical columns):

- 8 duplicate lab columns correctly dropped on merge (already present in
  `cases`, kept as source of truth)
- 0 duplicate case records
- ~30–50 implausible values flagged and imputed per run (varies slightly by
  which values happen to fall outside literature-based clinical bounds)
- 10+ numeric columns imputed via MICE, 6 categorical columns mode-imputed
- All 4 data-quality validation checks passing (schema, completeness,
  imputation plausibility, scaling sanity)
- **31/31 unit tests passing**, including edge cases (all-null columns,
  single-unique-value columns, unseen categories, empty-override behavior)

## Notable bugs found and fixed against real data

Running against the live API (rather than only synthetic test data) surfaced
issues no amount of unit testing alone would have caught — documented here
because working through them is a real part of the engineering story:

1. **Column collision on merge** — VitalDB's `cases` table already ships
   several preop labs built in. Re-fetching them from `/labs` caused pandas
   to silently create `_x`/`_y` duplicate columns on merge, breaking every
   downstream column-name lookup. Fixed by dropping pivoted lab columns that
   already exist in `cases` before merging.
2. **Wrong lab field name** — VitalDB labels glucose as `gluc`, not
   `glucose`; that lab was silently returning nothing.
3. **MICE extrapolation** — the data-quality validator caught a MICE-imputed
   value landing outside a clinically plausible range, since
   `IterativeImputer` is regression-based and can extrapolate (unlike KNN).
   Fixed with the `ImputationBoundsClipper` step.
4. **Unused raw columns failing completeness checks** — ~25 raw VitalDB
   fields the pipeline never chose to process were riding along untouched in
   the output, still carrying missing values. Fixed by adding `FeatureSelector`
   to explicitly scope the final output to intentional features only.
5. **`x or DEFAULT` silently ignoring explicit empty overrides** — a classic
   Python bug: an empty dict/list is falsy, so `bounds={}` was silently
   falling back to the real default instead of actually being empty. Caught
   by a unit test, fixed everywhere with an explicit `is None` check.
6. Minor: a `tabulate` dependency in the report writer and a Windows
   `UnicodeEncodeError` from a non-UTF-8 file write, both removed.

## Limitations

- **Single-institution, single-country, single time period** (2016–2017, one
  hospital in Seoul). A model trained on this data will not automatically
  generalize across populations, hospital protocols, or monitoring
  equipment.
- **Surgical/perioperative scope only** — this is not general EHR data;
  there's no chronic-disease progression or outpatient longitudinal data.
- **Outcome label coverage is not uniform** — if used for downstream
  prediction (e.g. mortality, ICU admission), check per-case label
  availability before treating any outcome column as fully populated.
- **MICE is slower than KNN** on larger datasets since it iterates a
  regression model per column; `max_iter` in `MissingValueImputer` is the
  first knob to reduce if runtime becomes a problem on the full case set.
